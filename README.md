# Fusion Studio

*A free, open-source workspace for TTP-driven threat research.*

Fusion Studio helps security analysts turn threat knowledge into organized research. Explore MITRE ATT&CK®, ATLAS and CAR reference content, select the techniques relevant to your topic, record your analytical notes, and save or export your work for further analysis and reporting.

Built for CTI analysts, independent security researchers and small research teams, Fusion Studio brings reference browsing, technique selection and research notes into a VS Code-inspired desktop workspace. The interface and operating manuals support English and Traditional Chinese.

## What you can do

- **Research threats:** explore groups, software, campaigns, techniques and procedure examples, then assemble the TTPs relevant to your research topic.
- **Keep your reasoning with your research:** add technique comments, reference links and metadata, and use supported layer scores and colors to express your own analysis.
- **Explore detection and AI security references:** browse CAR analytics, data models and sensors, alongside ATLAS techniques, mitigations and case studies. ATT&CK and ATLAS selections remain independent; CAR analytics are separate research entries in the Workplace.
- **Continue and deliver your work:** save and reopen research documents, compare supported ATT&CK layers and dataset versions, and export lists, matrices or tables for reports and presentations.

## Typical use cases

- Build a TTP research profile for a threat actor, malware family or campaign.
- Organize analyst-mapped techniques, notes and evidence links for an incident research summary.
- Prepare detection research or purple-team exercise scope and record items that need testing.
- Collect ATLAS references for an AI security study, or create technique-based teaching materials.

**Research workflow:** Explore → Select TTPs → Add notes and references → Compare → Save and export → Revisit and update.

Use **Studio JSON** to preserve editable research, including the content types selected when saving. Use **Navigator JSON** for supported ATT&CK layer exchange, **CSV** for tabular exchange, and **SVG / Excel** for supported matrix and analysis outputs. Formats preserve different content; see the [operating manuals](manual/README.md) for details.

## Application name and startup flow

### Fixed Windows title bar and border

Fusion Studio keeps its native Windows title bar and outer border dark in both active and inactive states, instead of inheriting the Windows accent color. The title bar uses `#181818`, the border `#303030`, and caption text `#d4d4d4`. Native dragging, resizing, maximize/minimize and close controls remain available. Qt main windows and Qt dialogs share this behavior; system-owned file-dialog decorations remain controlled by Windows.

`main.py::configure_application()` installs `windows_frame.py::FixedWindowsFrame` once. It reports **Window frame 1/3 prepare** with no file inputs or outputs, then **2/3 apply → 3/3 ready** for each new native top-level window. An application event filter reapplies the same DWM attributes when a native handle is created, a window is shown, focus changes, or its Qt palette changes. Only in-memory native window attributes are changed; no Windows personalization settings, registry entries or preference files are written. The process is documented here in the source directory.

The implementation uses Microsoft's [DWM window attributes](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute): dark frame mode, border color, caption color and text color. Explicit frame colors require Windows 11 build 22000 or later. Unsupported attributes are reported once and leave the supported native appearance in place. Non-Windows systems and Qt offscreen previews skip the native filter. Restart the application to load this change.

### Studio Files, Save and Recovery

**File → Open Studio JSON… / Ctrl+O** reopens complete Studio 1.0 documents, including independent enabled flags, annotations, domain/version archives, migration history and document identity. **Save / Ctrl+S** writes to the bound Studio path (asks on first use); **Save As… / Ctrl+Shift+S** binds a new filename/path. **Import Navigator Layer** now uses **Ctrl+Alt+O**. CSV/Navigator/SVG/XLSX remain exchange outputs and do not replace a full Studio save. A complete Studio JSON export also establishes a save baseline. `*` reflects changes against that baseline.

Closing a changed tab or exiting the application offers Save/Discard/Cancel. Save always writes complete Studio JSON, with all remaining tabs kept open after any cancellation or failure. Exit/Discard invalidates the recovery document list so discarded drafts cannot return; saved files remain on disk. A failed final checkpoint also keeps the application open. Save detects externally modified target files and requires reopening or a different Save As destination.

Normal startup owns `<project-root>/data/workspace-session.json` using a `.lock` companion. After edits settle for about 1.5 seconds, an immutable background checkpoint records up to 50 open documents, order/active tab, dirty drafts, saved paths/baselines, archives and primary view settings. It never automatically overwrites Studio files. **Next launch validates and automatically restores the entire previous session without a Yes/No/Cancel recovery question.** Once the workspace and any matrix columns are ready, the bottom Output panel is shown and announces automatic restoration, tab count, unsaved-tab count and absolute checkpoint path, in the selected interface language. A missing checkpoint starts a fresh workspace; an empty checkpoint reports that there are no tabs to restore. Failed/cancelled validation retains the original file and suspends its replacement; use **Restore last session…** to retry (manual restoration still asks before replacing open work) or **Start new recovery session…** to explicitly replace it. A clean saved exit also retains its tabs for the next launch. Default recovery artifacts are excluded from Git. `--no-session` disables automatic recovery while preserving manual saving/exit checks; `--session-file <path>` chooses an isolated checkpoint. Programmatic `MainWindow` construction leaves checkpoints disabled unless `session_path` is supplied, which keeps embedded/audit windows isolated.

Opening/recovery use exact cached official releases and verified custom Bundle hashes, including archived datasets. Missing releases/Bundles produce an error with no partial installation or silent ID removal; prepare them through Version or the custom STIX loader and retry. Saved JSON never initiates embedded URL fetches or changes official pointers. Studio/session input is bounded to 64 MiB, custom cached Bundles to 128 MiB. Search text and precise scroll positions are outside session restoration; crash recovery includes only the last completed checkpoint.

The matrix **Selection scope** controls support the platform scope (including hidden/collapsed entries), literal search matches (excluding hidden disabled entries), or visible expanded cells, optionally restricted to one tactic. **Select…** adds, replaces, removes or inverts that scope, or replaces the selection with annotated/unannotated matches. Tactic header context menus provide tactic-wide selection operations. Selection follows the document's cross-tactic/family preferences and never changes enabled flags or annotations; disabling cross-tactic synchronization permits partial tactic selections. ## Installation

The steps immediately below cover Windows. For native Linux or WSL2/WSLg, use [Linux / WSL2 Installation](#linux--wsl2-installation).

### Requirements

Use Windows PowerShell and **Python 3.11**, the Python version used to verify this project. Install Python from [python.org](https://www.python.org/downloads/) if needed. Git is optional if you download the source as a ZIP. First-time package installation and ATT&CK downloads require an internet connection.

The project can be placed in any writable folder on your computer. In this README, `<project-root>` means the absolute path of that folder. Run the commands below from the folder containing `main.py` and `requirements.txt`; all executable commands use paths relative to it.

### 1. Get the Project

Clone the repository into your chosen parent directory:

```powershell
git clone https://github.com/NicoaTheSix/MITREATTACK_SIMULATOR.git
Set-Location -LiteralPath '.\MITREATTACK_SIMULATOR'
```

Alternatively, download **Code → Download ZIP** from the [repository](https://github.com/NicoaTheSix/MITREATTACK_SIMULATOR), extract it, and open PowerShell in the extracted project folder. If you already received an extracted source folder, start there.

### 2. Create a Virtual Environment and Install Dependencies

Create a new `.venv` inside your own copy of the project:

```powershell
Write-Output ('Output directory: ' + (Join-Path (Get-Location).Path '.venv'))
py -3.11 -m venv .venv
Write-Output ('Input file: ' + (Resolve-Path '.\requirements.txt').Path)
Write-Output ('Output directory: ' + (Join-Path (Resolve-Path '.\.venv').Path 'Lib\site-packages'))
& '.\.venv\Scripts\python.exe' -m pip install -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' -m pip check
```

If `py` is unavailable, check `python --version`. When it reports Python 3.11, use `python -m venv .venv` instead of `py -3.11 -m venv .venv`. The dependency installation and check must finish successfully before proceeding. Each computer should create its own virtual environment.

### 3. Download ATT&CK Data

For a fresh checkout, download the latest official stable ATT&CK snapshot:

```powershell
& '.\.venv\Scripts\python.exe' -B '.\scripts\download_attack_data.py'
```

The script prints resolved absolute paths and progress, downloads Enterprise/Mobile/ICS bundles, validates them, and writes the snapshot and `latest.json` inside this project's `data\attack` directory. HTTPS access to `api.github.com` and `raw.githubusercontent.com` is required. Wait for **5/5 Publish — Complete** before starting the interface. You can skip this step if your project copy already includes a valid snapshot and its pointer. See [scripts/README.md](scripts/README.md) for the download workflow and error handling.

### 4. Start the Application

```powershell
& '.\.venv\Scripts\python.exe' -B '.\main.py'
```

Wait for catalog-loading progress to finish. **Fusion Studio** opens with a new Enterprise document. Select TTPs, or right-click the filename to choose Mobile or ICS. Keep the terminal open while the application runs. Export documents you want to retain before using **File → Exit / Ctrl+Q**.

For later launches, open PowerShell in the same project folder and run only the command in this step. Cached-data startup and local browsing work offline.

### Optional: Activate the Environment or Open an Editor

The commands above use the environment's Python directly. To activate it instead:

```powershell
& '.\.venv\Scripts\Activate.ps1'
python -B '.\main.py'
```

After closing the application, `deactivate` leaves the environment. If PowerShell blocks `Activate.ps1`, use the direct `.venv\Scripts\python.exe` command in step 4.

To inspect the source in VS Code, use **File → Open Folder** and select your project folder, or run `code .` if that command is installed. Select your project's `.venv\Scripts\python.exe` as the Python interpreter.

### Troubleshooting

- **Missing Python or packages:** verify Python 3.11 is installed and repeat step 2 using your project's `.venv` interpreter.
- **Missing or invalid ATT&CK data:** repeat step 3 and inspect the terminal/Output messages. Startup uses `data\attack\active.json` when present, otherwise `data\attack\latest.json`, and validates the referenced local bundles.
- **No visible window after an offscreen audit:** clear that PowerShell session's preview setting before launching again:

  ```powershell
  Remove-Item Env:QT_QPA_PLATFORM -ErrorAction SilentlyContinue
  ```

Startup displays absolute input paths before reading files and reports Resolve → Read → Index → Tree progress. Ordinary startup and local browsing use cached data without network requests; Studio saves and automatic workspace checkpoints preserve document work locally.

### Processing and Visible Progress

1. **Resolve:** show input/output paths, read the snapshot pointer and manifest, and verify version agreement.
2. **Read:** read the Enterprise bundle in chunks with byte progress, check its size and SHA-256 against the manifest, and parse its JSON with an activity indicator.
3. **Index and library:** exclude revoked/deprecated records, index active techniques and tactics, resolve `subtechnique-of` relationships, and map `x_mitre_platforms` with `mitre-attack` kill-chain phases. Verify and read the Mobile/ICS bundles and index the six library categories. Report object, mapping, and transfer progress.
4. **Tree and navigation lists:** construct Platform → Tactic → Technique branches in small GUI batches, nest sub-techniques under their parent, and populate the six library category models in batches of 100 entries. Display progress and enable category buttons once loading completes.

File reading and indexing run in a background Qt thread. Tree construction runs in timer batches in the UI thread. The Output panel records stage progress and errors; the status bar shows the active stage and progress bar. Closing during loading requests cancellation and waits for the worker to finish before destroying the window.

## Version Selection Workflow

The top menu bar contains **Version (vX.Y)**. Open it to search all Enterprise ATT&CK releases in the official [STIX collection index](https://github.com/mitre-attack/attack-stix-data/blob/master/index.json), sorted numerically newest first. The picker shows matching domain availability, the index date in UTC, and Current / Downloaded / Download status. Opening the picker refreshes the official list in a background thread; **Refresh online** repeats discovery. Regular startup stays offline. If discovery fails, the cached official index remains available and the picker labels the failure. **Switch version** downloads a missing snapshot, verifies it, rebuilds the tree and library categories, and updates the displayed version. Existing versions switch offline after integrity checks. A zero-entry category reflects absent objects in that historical release.

`attack_versions.py` implements discovery, cache management, immutable-commit downloads and validation. `version_dialog.py` provides the picker and background worker. Both are documented here in the same source directory. `attack_catalog.py` accepts a selected snapshot pointer and treats absent historical Mobile/ICS domains as empty; it never mixes a different release into the selected one. The picker covers every numeric Enterprise release advertised by the official index. Mobile-only beta release labels are not separate Enterprise versions; only exact domain version matches are loaded.

Input paths are resolved before use: the data root (default `<project-root>\data\attack`), cached `versions-cache.json`, snapshot `vX.Y\index.json` and `manifest.json`, and each versioned domain bundle. Network inputs are official GitHub API and raw HTTPS URLs and are logged explicitly. Output paths are displayed before writing: `versions-cache.json` and its `.part` file; `vX.Y\index.json`, `LICENSE.txt`, available domain bundles, `manifest.json`, `README.md`, and corresponding unique `.vX.Y-<uuid>` staging paths; then `active.json` and `active.json.part`. Metadata-only reads produce no output file. UI progress appears in the picker, main Output pane, status bar, and terminal.

1. **Discover (1/4):** resolve the upstream master commit, read its pinned index, validate official domain URLs, and atomically cache the index. Display cached status if offline.
2. **Prepare/download (2/4):** validate an existing local snapshot or download only matching domains into a unique staging directory; display absolute paths and transferred bytes.
3. **Validate (3/4):** check bundle structure, collection version and technique domains; compute manifest sizes/SHA-256; load every available domain and procedure index before publishing the completed snapshot directory.
4. **Switch (4/4):** atomically save `active.json`, change only the active document's catalog, rebuild all models, reset stale searches/details, retain selected STIX IDs present in the new catalog, and report selections absent from the new version. Other documents retain their prior selections and catalog references. Activating a document restores its verified in-memory snapshot without a new download or changing `active.json`. Sidebar, procedure examples, copy actions and JSON export use that document's release.

`latest.json` continues to describe the downloader's latest snapshot. `active.json` records the user's version choice for the next desktop launch. An unreadable/invalid saved choice falls back to `latest.json` with visible progress. Download, validation or persistence failures leave the current interface and previous active pointer usable. Damaged existing cache directories are preserved and reported rather than overwritten. Cancel/Close cooperatively stops at the next progress boundary; an active HTTPS read can take up to its 30-second socket timeout. No background data request is made at application startup. The full `audit_catalog.py` audit explicitly checks `latest.json`; `audit_versions.py` independently exercises discovery, historical loading, switching, failure preservation, and restart persistence.

No modern tactic records or fabricated official TA identifiers are inserted. Existing tactic objects and matrix ordering remain authoritative when present.

### JSON Format

The exported UTF-8 JSON uses `schema_version: "1.0"` and includes:

| Field | Content |
| --- | --- |
| `document_id`, `name` | Stable document UUID and exported filename stem |
| `created_at_utc`, `exported_at_utc` | Document creation and export timestamps |
| `attack` | Document domain (`enterprise-attack`, `mobile-attack`, or `ics-attack`), actual dataset version, and official source URL |
| `selected_count` | Number of unique selected techniques/sub-techniques |
| `selected_technique_ids` | Sorted ATT&CK IDs, such as `T1053.005` and `T1059.001` |
| `navigator_import_selected` | Raw Navigator import-selection bookkeeping for exact editable restoration |
| `selection_scopes`, `selection_preferences`, `search_fields` | Partial tactic inclusion, cross-tactic/family behavior and enabled TTP search fields |
| `selected_ttps` | One row per selection: `technique_id`, `stix_id`, `name`, `is_subtechnique`, `parent_technique_id`, `parent_technique_name`, `platforms`, `tactics`, `comment`, and `tactic_comments` |

Each tactic contains `tactic_id`, `name` and `shortname`; historical snapshots with no official tactic object export `tactic_id: null` for derived phase headings. `parent_technique_id` and `parent_technique_name` are null for a parent technique. Platform/tactic metadata reflects the source technique's complete mapping, not just the branch in which its box was checked. Techniques are sorted by ATT&CK ID and STIX ID for consistent output; this order describes a selection list rather than an execution sequence. An actual example generated by the document audit is available at [artifacts/selected-ttps-example.json](artifacts/selected-ttps-example.json).

Unknown/inactive IDs and tactic mismatches appear in the resolution column; they remain preserved annotation rows but are excluded from selection. Import commits only after **Open selected layers**, creating independent tabs with synchronized tree/matrix selections and activating the first checked layer.

Each layer retains its own choice of enabled rows (or explicit Studio selection metadata), all listed rows, or rows with a score/color. A score of zero is still a scored row. Repeated rows for the same ID are deduplicated for document selection while tactic-specific annotation rows remain separate. Cancel, read/validation errors, and failed snapshot preparation leave existing documents untouched. Reference links remain data. Embedded `customDataURL` sources are fetched only through **Resolve custom data… → Fetch / Validate source**; exact loaded catalogs and hash-verified caches still resolve offline. Missing or ambiguous sources are acquired/selected and reviewed within the same preview, with explicit consent for changed hashes. Navigator annotations represent more than document selection. Export records an explicit `TTP Selection Studio selected` marker in standard row metadata so an application-generated file can restore its exact selected IDs. `navigator_integration.py` invokes the SDK's `Layer` parser to validate supported structures, with explicit checks for IDs, finite scores, colors, gradients, legends and schema versions. This avoids precision loss and unbounded SDK curve allocation. No SDK source files are patched.

### Score Formulas, Family Aggregation and Matrix Exports

**Navigator → Create layer from score formula…** maps compatible open documents to `a`–`z` (maximum 26), shows their names, and creates a separate result document. Sources must match the active domain, version and exact dataset; Navigator operations require official ATT&CK v4+ or compatible custom data. In **Formula and scope**, the default **Calculation mode: Studio** lets you choose **Selected TTP union from referenced sources** (default, retaining partial tactic scopes) or **Entire matrix**. Entire matrix calculates every active mapped technique/sub-technique/tactic cell, regardless of selection, platform/search filters, disabled visibility or collapsed children. A constant `50` therefore scores the full matrix even when no source TTP is selected. Selected scope uses all listed sources for a constant; inheritance-only sources do not enlarge a variable formula's target set.

Supported scalar formulas include `+ - * / % ^` (power), unary signs, `< <= > >= == !=`, `and / or / xor / not`, and `condition ? yes : no`. Comparisons and boolean results are numeric 1/0; nonzero is true. Powers associate right-to-left, before unary signs (`-2^2` is -4). Conditional branches and `and`/`or` short-circuit arithmetic evaluation. **Formula syntax** explicitly separates the new **Navigator scalar** default in the dialog from **Studio scalar**, which retains earlier arithmetic semantics; the Python API still defaults to Studio. Existing saved results are never recalculated automatically.

NAV-018 adds constants `pi`, `e`, `tau`, `phi`, `true`, `false`; trigonometric `sin/cos/tan`, `asin/acos/atan/atan2`; hyperbolic `sinh/cosh/tanh`, `asinh/acosh/atanh`; `log2/log10/log1p`, `expm1`, `cbrt`, `sign`, `fix`, and `mod`. Existing `abs/min/max/round/floor/ceil/sqrt/pow/log/exp` remain available. Angles use radians. In Studio calculation mode, a listed source layer `e` shadows Euler's constant; use `exp(1)` in that case. Navigator calculation mode first probes an empty scope, as described below. Navigator syntax lowercases the complete input, supports adjacent chained comparisons (`3>2>1` → 1) and infix `mod`, and uses mathjs-style comparison tolerances (relative 1e-12, absolute 1e-15). Its `round` rounds halves away from zero (`round(-2.5)` → -3), with roundoff correction; `round/floor/ceil/fix` accept integer decimal precision 0–15. Navigator `%` and `mod` use floor-based remainder, including `mod(3,0)` → 3. Studio retains ties-to-even `round`, precision ±100, earlier `not` precedence, exact comparisons and zero-divisor rejection for `%`; write Studio chained comparisons with `and`. The new case-sensitive `nthRoot(value[,root])` is a Studio extension: the official lowercasing pipeline makes `nthRoot` unavailable in Navigator syntax. This implements a verified scalar subset, not all mathjs expressions. See the [English formula manual](manual/layer_score_formulas_en.md) / [中文公式手冊](manual/layer_score_formulas+_zh.md) for examples and differences.

### Selection and Version Comparison

**Navigator → Compare open TTP documents…** displays common techniques, left-only techniques and right-only techniques for two open documents using the same ATT&CK version and domain. It exports a validated Navigator Layer with a legend: green = both, blue = left only, orange = right only. Comparing different domains or snapshot versions is explicitly rejected; comparisons do not modify the source documents.

**Navigator → Compare ATT&CK versions…** compares two downloaded snapshots for the active document's Enterprise, Mobile, or ICS domain through the SDK's actual `DiffStix` engine. It verifies both snapshot manifests/hashes before processing local STIX **2.1** bundles. The native result table includes SDK classifications for additions, major/minor/other changes, patches, revocations, deprecations and deletions across supported object types. It also lists selected IDs unavailable in the target version, helping review migration impact before using the existing Version switch. An absent historical domain fails explicitly. The comparison itself does not switch versions, migrate IDs, modify selections or write dataset pointers.

The SDK reads standard `<domain>.json` filenames, so the adapter copies verified bundles into a generated `artifacts\sdk-diff-<random>` staging directory. Absolute input/temporary output paths are displayed before file copies. The directory is automatically removed after completion or an exception. An explicit **Export version comparison JSON…** writes the SDK result plus domain, versions, format and selection impact. The result's release labels come from verified manifests; the SDK may print an unknown-release-hash notice for these Collection bundles without preventing the STIX comparison. No network access is required for comparing already downloaded snapshots.

**Navigator → Open ATT&CK Navigator website** opens the official browser application only when clicked. Exported layers can then be opened using Navigator's layer-file loading controls. The desktop does not automatically upload documents or annotation files.
