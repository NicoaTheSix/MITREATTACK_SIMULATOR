# 解析圖層的 customDataURL

## 在匯入預覽內取得來源

1. 選 **File → Import Navigator Layer…／Ctrl+Alt+O**，開啟 Navigator JSON 物件或陣列，再點選清單中的自訂圖層。
2. 按 **解析自訂資料…**，開啟該圖層的來源檢視視窗，可看到名稱、領域、記錄版本、`customDataURL` 與預期資料集 SHA-256。開啟視窗不會發出下載請求。
3. 使用可編輯來源欄位與 **取得／驗證來源** 讀取指定 HTTP(S) 網址。也可按 **瀏覽 Bundle…** 選本機 JSON Bundle；或用 **選擇快取的 Bundle…** 填入快取絕對路徑，再按取得／驗證。快取清單最多列出 1,000 個雜湊檔名 JSON，列出不代表已驗證為 Bundle。
4. 若來源是 Collection Index，請選其中一個版本，再按取得／驗證。系統不會自動挑選或下載其參照 Bundle；不論 Index 標籤為何，實際 Bundle 必須符合圖層記錄版本及指定領域。
5. 檢查解析來源、最終來源、預期／實際 SHA-256、快取輸出絕對路徑、領域、版本、已選取 TTP 數與未解析註記列數。按 **使用已驗證的 Bundle**，只會把來源套用至該圖層並回到同一份匯入預覽，尚不建立文件。
6. 補齊其他勾選圖層後，按 **開啟勾選圖層**。所有勾選圖層都就緒才會依原 JSON 順序整批開啟，既有文件維持原狀。

確切已驗證的已載入資料集或 Bundle 快取仍可離線自動解析。只有 URL 的圖層，若已有唯一一份 URL／版本／領域相符的已載入資料，也能先解析；同 URL 有多個雜湊則需明確選擇。URL-only 圖層開啟來源檢視時，若已解析出資料集，會以其雜湊作為預期值。

## 相對參照與轉址

本機 Navigator 檔案的相對 `customDataURL` 以該 JSON 所在目錄解析；瀏覽按鈕一律填入本機絕對路徑。透過 **File → Load layer URL / custom STIX…** 載入的圖層，其相對網路參照會以轉址後的最終 Navigator 網址解析，不會錯用下載快取目錄。Collection Index 的相對 Bundle 網址也以 Index 最終網址解析。

只支援 HTTP(S) 網址與明確本機路徑；其他網址協定、內嵌帳密、不合法連接埠或控制字元會被拒絕。HTTP 轉址須維持 HTTP(S)，轉址迴圈會失敗。用替代本機 Bundle 取得內容時，圖層仍保留原指定來源作為來源身分，實際取得位置與最終網址／路徑另外記錄。

## 來源內容改變

資料集身分是取得檔案原始位元組的 SHA-256。因此即使物件語意相同，重新排版 JSON 也可能改變雜湊。

實際雜湊與原記錄／已解析資料集不同時，**使用已驗證的 Bundle** 預設停用。可改選原始 Bundle；或確認來源及未解析技術後，勾選 **我確認以此內容已變更的 Bundle 取代原先記錄的資料集**，再按使用。修改或重試來源會清除上次候選資料與確認；請求失敗不能沿用舊的驗證結果。

取代只影響正在檢視的圖層。同網址的其他圖層各自保留資料集；新雜湊寫入另一個快取，不覆蓋原雜湊。已不存在的技術仍保留成未解析註記列並統計，不會自動勾選或猜測對應 ID。此流程只處理相同領域／版本的來源替換；跨版本請使用升級審查流程。

範例：圖層記錄 `https://example.org/bundle.json` 的雜湊 A，但網址現在回傳同版本的雜湊 B。預覽顯示兩者；取消仍使用 A，明確確認取代後才將本次匯入圖層綁定 B，並保留 A 快取供其他圖層使用。即使確認取代，錯誤版本／領域仍不能接受。

## 驗證、檔案與取消

沿用 ATT&CK 相容 Bundle 驗證：STIX 物件 ID／型別、最新版本、欄位、有效技術、Tactic、Matrix 與父子關係。來源上限 **128 MiB**，Bundle 上限 **200,000 個物件**，Collection Index 上限 **1,000 個版本選項**，HTTP socket 等待上限 **20 秒**。過大的 Content-Length 在讀取前拒絕，串流也有位元組上限。雜湊檔名快取的實際內容不符檔名時直接拒絕；不會以同版本官方資料替代自訂來源。

處理前 Output 會列出輸入絕對路徑或 URL，檢視階段明確顯示沒有輸出檔案。進度為 **1/5 取得 → 2/5 解析／Index → 3/5 驗證與檢視 → 4/5 快取接受內容 → 5/5 綁定預覽**，並顯示底層讀取／解析／建目錄／快取進度。寫快取前會列出實際輸出及暫存檔絕對路徑。單純檢視不寫檔；接受後才原子寫入 `<project-root>/data/attack/custom/<sha256>.json` 並更新記憶體內匯入草稿。官方 `active.json／latest.json` 與輸入 Navigator 檔不變。

接受前取消不改變綁定；讀取、驗證或快取期間取消，會在工作執行緒檢查點中止，延遲完成的結果不會綁定或開啟文件。已完成的有效快取可能留下，但不安裝部分文件。若正在等待 HTTP 讀取，可能須等到 socket timeout 才完成取消。

接受的草稿會記錄完整 `customDataURL`、確切 `x_ttp_studio_dataset` 與 `x_ttp_studio_source_review`：原指定／解析／實際取得／最終位置、原雜湊／新雜湊及明確取代同意。Studio 儲存／重新開啟、Navigator 再匯出及工作階段復原均會保留。跨電腦攜帶 Studio 文件時，也須提供確切 Bundle 快取；來源亦可能是本機路徑。

## 驗證方式

設定 `QT_QPA_PLATFORM=offscreen`，用專案環境執行 `python -B audit_custom_data_url.py`。測試先列出絕對輸入／輸出，再使用隔離本機 HTTP 伺服器與 fixture 快取，將截圖、往返檔案及 `audit.json` 寫到 `<project-root>/artifacts/custom-data-url`。涵蓋轉址、相對參照、失效／格式錯誤／過大來源、領域／版本／雜湊錯誤、來源變更確認、Collection 明確選擇、快取驗證、取消、整批安裝與 Studio／Navigator／復原；不需下載公網資料。
