# 升級前後內容並排比較與目標註記編輯

開啟 **Navigator → Review and upgrade layer…（審閱並升版圖層）**，選擇同領域目標並按 **Load target and compare**。上半部保留完整技術審核與來源註記搬移表；下半部的 **Content comparison（內容並排比較）**提供各自可捲動的「升級前／升級後」內容。可拖動中間的水平分隔線，增加比較區空間。

## 檢視兩份快照

在「技術逐項審核」選技術，可看完整來源／目標記錄與對應註記列。在「註記搬移決策」選列，則查看該來源範圍、目前指定目標與修訂後註記。更換目標技術會更新右側。同技術有多個來源註記列時，請先選要編輯的那一列。

每側顯示 ID／名稱、確切資料集版本／領域、自訂資料集雜湊、有效／撤銷／棄用狀態、Description、Tactic 名稱與 slug、Platform、註記，以及包含擴充欄位的完整 STIX JSON。原始描述與使用者文字經跳脫，不執行或下載嵌入 HTML／圖片。完整原始記錄可向下捲動查看；**Raw differences（原始欄位差異）**保留既有逐欄 JSON 差異與原註記。

快照沒有記錄時會明示空狀態。撤銷／棄用記錄仍可閱讀，但不能當成有效搬移目標。目標 Tactic 已移除或不合法時，須先指定有效映射才能編輯。Drop 不顯示複製後註記。左側始終使用原始快照，目標草稿不會修改它。

## 開啟對應版本頁面

官方記錄的兩側各提供 **Open version page…（開啟對應版本頁面）**。例如資料集 v11.3 的 T1053.005 對應候選網址為 `https://attack.mitre.org/versions/v11/techniques/T1053/005/`。介面會區分本機確切資料集版本與網站主版本封存；網站頁面不保證與指定修補版本完全一致，精確比較以本機 STIX 為準。

點擊後由背景工作先檢查指定頁面，再啟動系統瀏覽器。只接受同一官方 HTTPS 封存、技術與子技術，允許等價的 `index.html` 路徑。缺頁、逾時、錯誤或轉址到其他版本／ID／目前網站，都會顯示失敗，不會改開最新版。驗證成功才開啟原指定版本網址；檢查期間關閉視窗，不會延遲啟動瀏覽器。網站可用性可能改變，本機內容仍可離線閱讀。

自訂資料集不會虛構官方版本頁，即使其外部參照指向 MITRE 也是如此。快照缺少記錄時也不提供版本頁按鈕；兩者皆保留本機內容。本功能不會自動存取自訂參照網址。

## 編輯既有映射的目標註記

在「註記搬移決策」選 **Copy**、有效目標技術及 Tactic（或 All tactics），再按比較區下方的 **Edit target annotation…（編輯目標註記）**。編輯器會載入原本將複製到該目標的註記，可修改 Comment、Score、Color、Enabled、Links、Metadata。空白 Score 會移除儲存分數；空白顏色／註解及空清單會清除對應欄位。

目標 ID／Tactic 由映射列控制，編輯器的 Tactic 選單鎖定，不提供加入選取的選項，因此編輯註記不會更動選取或擴大範圍。替代技術也使用相同流程：先指定替代目標與有效範圍，再修訂註記。

儲存後只更新該來源列的記憶體草稿，刷新右側，並清除來源列及技術的已審狀態；請重新檢查並確認。取消保留先前已存草稿。之後若明確重新映射，編輯欄位會跟隨新目標，仍須重新審核。選 Drop 則結果不套用該列及其草稿，審核紀錄保留這項決策。更換／重新載入目標或關閉升級視窗，會清除尚未提交的草稿。

只允許上述六種註記欄位，不接受透過註記補丁改寫 ID、Tactic 或其他圖層屬性；無關的原始註記擴充欄位會保留。分數須有限、顏色合法、結構化欄位有效，修改的連結須 HTTP(S)。相容來源列可合併；未解決的純量衝突仍阻擋搬移，可透過[一對多映射與欄位衝突審核](upgrade_mapping+_zh.md)明確處理。

## 加註原本沒有註記的目標

原本沒有來源註記／選取列的技術，可在「技術逐項審核」選取後按「編輯目標註記」，建立獨立目標草稿，不會自動選取。已有來源列者會帶到第一筆映射，必要時請另選其他列。Added 仍保留「編輯新增技術註記」及預設不勾選的加入選項，詳見[完整技術審核手冊](upgrade_review+_zh.md)。

## 建立與保存

處理映射並審核全部技術後，**檢視最後摘要… → 提交升級** 會驗證修訂列、獨立目標草稿及所有確認，再安裝新文件。原文件與完整來源封存不變。`x_ttp_studio_upgrade.decisions[].annotation_patch` 保存映射編輯；`technique_reviews[].annotation_rows` 保存獨立目標註記。Studio 儲存／重開、session 復原及 Navigator JSON 保留結果註記與審核來源；完整原始封存由 Studio JSON 保存。

註記操作先明示記憶體輸入／無輸出檔案，再回報編輯進度。比較與搬移依 **Upgrade 1/3** 比較 → **2/3** 驗證套用 → **3/3** 完成顯示進度。版本頁檢查先顯示確切輸入 URL／無輸出檔案，再依 **Upgrade page 1/2** 檢查 → **2/2** 驗證完成。資料載入及匯出另列絕對檔案路徑；草稿不會在 Save／Export 前自行寫檔。

## 驗證方式

於專案根目錄安裝相依套件並快取官方 v11.3 後：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
& '.\.venv\Scripts\python.exe' -B '.\audit_upgrade_content.py'
```

七階段先列絕對輸入／輸出路徑，再測固定快照 → 完整／跳脫內容 → 目標補丁驗證 → 原生並排／編輯／取消／重新映射 → 版本 URL／錯誤／瀏覽器處理 → Studio／session／Navigator 往返 → 真實歷史子技術 URL／內容與報告。HTTP 回應與瀏覽器啟動使用測例替身，驗證程式行為，不宣稱所有公開封存都可連線。產物、獨立快取與中英文截圖在 `artifacts/upgrade-content`，報告為 `audit.json`；已登錄於 `scripts/audit_linux.py`。

流程參照[Navigator v5.3.2 Mapping Annotations](https://github.com/mitre-attack/attack-navigator/blob/v5.3.2/USAGE.md#mapping-annotations)。網站主版本與個別修補資料的區別可參閱[MITRE 2022 年四月版本頁](https://attack.mitre.org/resources/updates/updates-april-2022/)。[手冊索引](README.md)。

最後提交會先經過[完整摘要、選填略過理由及返回未完成項目](upgrade_summary+_zh.md)。
