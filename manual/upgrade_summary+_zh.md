# 升級最後摘要、略過理由與返回未完成項目

開啟 **Navigator → Review and upgrade layer…（審閱並升版圖層）**，載入相同領域的目標，依序確認[完整技術分類](upgrade_review+_zh.md)、[並排內容](upgrade_content+_zh.md)與[映射／衝突決策](upgrade_mapping+_zh.md)。按 **檢視最後摘要…（Review final summary…）**，尚未審完也可開啟，查看還有哪些工作。

## 閱讀最後摘要

上方顯示來源／目標版本及領域、完整技術已審／總數、Copy／Drop 來源列數、輸出註記列數、選取技術／Tactic 範圍數，以及已解決／總衝突數。映射不合法而無法建立完整計畫時，未知輸出數顯示破折號。每個選取範圍代表一項技術在一個目標 Tactic 下的選取，與註記列數不同。

「分類摘要」固定列出 Added／Changed／Removed／Replaced／Unchanged。分母採完整技術比較，包含分類、僅有註記及僅待審篩選隱藏的項目。每類清楚顯示空白、未完成、已略過或已完成。來源映射或相關衝突檢查失敗，即使全部已勾審核，該類仍顯示未完成。整類全部略過時顯示已略過；混合保留與略過的分類，審完後顯示已完成。略過技術指沒有獨立註記／加入草稿的 Added，或其來源列全部 Drop、且沒有獨立目標註記的技術。零項分類顯示空白，不會阻擋提交。

只有全部技術／來源審核、目標範圍、獨立草稿、名稱與目前衝突決策通過驗證，才可按「提交升級」。開啟摘要本身不會自動審核、改變選取或註記。成功提交建立獨立目標文件，原文件保持完整。

## 編輯選填略過理由

「略過項目與理由」列出每筆 Drop 來源列，以及未建立獨立註記／加入草稿的 Added 技術。動作及技術／範圍清楚標示略過的內容。理由可留白，每筆最多 4096 個 Unicode 字元，可換行。

可直接編輯表格的「略過理由」，或選取一列／多列，在下方多行輸入框填寫，再按「將理由套用至選取的略過項目」。只在輸入框打字而未按套用的文字，不會保存。套用只更改選取項目的理由，不更改 Copy／Drop、註記、加入狀態或已審狀態。

「返回審核（保留理由）」會將理由草稿留在目前升級視窗；「取消」會捨棄這次摘要內的修改，保留先前草稿。透過未完成項目返回也會保留理由。重新開啟摘要可再次編輯。將 Drop 改回 Copy 後，結果不輸出該理由；再切回 Drop 仍可沿用草稿。重新載入目標或關閉升級視窗，會捨棄全部尚未提交的草稿；這些視窗草稿不會寫入工作階段復原檔。

略過 Added 的「新增註記」，代表不另建立獨立目標註記，**不會取消映射到該新技術的 Copy**。例如舊技術被新 ID 取代時，仍可搬移舊註記，同時略過新 ID 額外的 Added 註記。

## 返回未完成工作

「未完成項目」列出完整比較中的待審確認、無效來源目標／草稿、無效檔名，以及未解決、過期或無效的欄位衝突。被篩選隱藏者也會列出；同一來源可能有多項問題須分別修正。

- 選取問題後按「返回選取的未完成項目」，或直接雙擊該列。
- 「返回第一個未完成項目」會立即帶回第一項問題。
- 技術問題會定位完整審核列；來源問題會定位確切映射列，並清除分類、僅有註記及僅待審篩選，捲動顯示該列。
- 名稱問題會選取輸出名稱；衝突問題會重開目前衝突審核，能識別時定位目標／Tactic／欄位。過期或整體結構問題會返回對應審核區域。

修正後按需要重新審核，再開摘要。快照指紋綁定來源、目標、映射、審核、衝突決策與輸出名稱；輸入改變後舊摘要不可提交，須重新預覽。衝突亦保有獨立候選內容指紋。取消或驗證失敗不會安裝半成品。

## 操作範例

1. 載入新版，將一筆已移除來源設為 **Drop**。
2. 審核全部技術，包含沒有註記的 Added；刻意保留一筆 Changed 來源未勾已審。
3. 按「檢視最後摘要…」，確認完整分類數量及尚無法提交的狀態。
4. 在 Drop 列填入 `本次升級不涵蓋此技術，保留舊版證據` 並套用。
5. 返回未完成來源，檢視後勾選已審。
6. 重開摘要，確認理由仍在，再按「提交升級」。
7. 透過 **Save／Save As…** 保存完整 Studio 文件，或匯出 Navigator JSON 交換。

## 保存內容與程式流程

`x_ttp_studio_upgrade.final_summary` 保存分類數量／狀態、輸出數、來源／目標資料集識別，以及目前略過項目／理由。Drop 來源決策與略過 Added 審核亦加入 `skip_reason`。外層審核 schema 維持 `2`，摘要 schema 為 `1`，空理由明確保存。Studio 的 `migration_archives` 保留完整來源。Studio 儲存／重開、結果文件的自動工作階段復原及 Navigator JSON 都保留摘要擴充；其他應用可能忽略 Studio 擴充欄位。

計算前先報告輸入為記憶體、沒有輸出檔案。「Upgrade summary 1/3」完整比較及驗證理由／審核 →「2/3」驗證全部映射、草稿及目前衝突 →「3/3」顯示可提交狀態。套用理由顯示「Skip reasons 1/2 → 2/2」。提交會重新執行後端驗證，再依既有「Upgrade 1/3 → 3/3」建立文件。Save／Export 另外顯示絕對輸入／輸出路徑及寫檔進度；預覽／審核不寫檔。

程式流程：`source_dialogs.py` 擷取決策，協調背景摘要、返回與提交 → `upgrade_summary.py` 驗證理由、彙整完整狀態及指紋 → `upgrade_summary_dialog.py` 顯示摘要與局部理由草稿 → `layer_upgrade.py` 再次驗證並保存最終審核紀錄。各模組共用根目錄 README 的流程說明。

在專案根目錄執行：

```powershell
$env:QT_QPA_PLATFORM = 'offscreen'
& '.\.venv\Scripts\python.exe' -B '.\audit_upgrade_summary.py'
```

離線驗證先列輸入／輸出絕對路徑，依序測試快照 → 未完成輸入／理由 → 衝突／空結果／指紋 → 原生視窗／理由／返回 → 提交／過期／失敗／關閉安全 → Studio／session／Navigator → 發布報告。產物位於 `artifacts/upgrade-summary`，含 `audit.json`、`pending-en.png`、`summary-en.png`、`summary-zh.png`。已登錄 Linux 驗證程式；原生 Linux 執行仍是獨立平台驗證。
